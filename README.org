** Flavours Overview

This repository provides 26 pre-built container images across 5 distributions with
composable layers. Each image is built from a single template using build args to
select the base image and layer combination.

| Distro   | Images                                                         |
|----------+----------------------------------------------------------------|
| Arch     | cider, emacs, latex, emacs-ai, emacs-latex, emacs-latex-ai, ai |
| Fedora   | cider, emacs, latex, emacs-ai, emacs-latex, emacs-latex-ai, ai |
| Alpine   | emacs, latex, emacs-ai, emacs-latex, emacs-latex-ai, ai        |
| Debian   | cider, ai, claude-desktop                                      |
| OpenSUSE | emacs, emacs-ai, ai                                            |

The available layers are:

- *cider* — Cider, a cross-platform Apple Music client
- *emacs* — Emacs editor, plus the CLI tooling it leans on (ripgrep, fd, pandoc, R, uv, …)
- *latex* — LaTeX build tools
- *ai* — AI tools via npm (claude-code + opencode + gemini-cli + pi-coding-agent), with ACP adapters for [[https://github.com/xenodium/agent-shell][agent-shell]] (claude-agent-acp + pi-acp), plus the [[https://cli.github.com/][GitHub CLI]]
- *claude-desktop* — Claude Desktop for Linux (beta), via Anthropic's apt repository

Layers compose: =emacs-latex-ai-arch= is the =emacs=, =latex= and =ai= layers on the Arch
base, while =ai-arch= is the =ai= layer on its own.

** Build System

*** Architecture

All images share a single [[file:containerfiles/base.containerfile][base containerfile template]] customized using build arguments.

*** Build Arguments

| Arg        | Description                           | Example                              |
|------------+---------------------------------------+--------------------------------------|
| BASE_IMAGE | Upstream toolbox image                | ghcr.io/ublue-os/arch-toolbox:latest |
| LAYERS     | Comma-separated list of build scripts | emacs,latex,ai                       |

*** CI Pipeline

The [[file:.github/workflows/build-and-publish.yml][build-and-publish workflow]] builds all 26 images from the matrix in
[[file:.github/matrix.yaml][=.github/matrix.yaml=]]. Each entry specifies:

- *image-name* — Output image name (e.g., =emacs-latex-ai-arch=)
- *base-image* — Upstream toolbox base image
- *layers* — Comma-separated layer scripts
- *context* — Build context directory (=./context/<distro>=)

That matrix is also the source of truth for =distrobox.ini=, which
[[file:scripts/gen-distrobox-ini.sh][=scripts/gen-distrobox-ini.sh=]] regenerates via pre-commit. The generated file is
committed, and CI fails if it is out of date.

Every build produces a cryptographically signed image with SLSA Level 3 provenance
via [[https://github.com/MArpogaus/image-builder-action][image-builder-action]].

** About The Project

This repository contains containerfiles for building signed container images optimized for use with [[https://github.com/89luca89/distrobox][distrobox]] and [[https://github.com/containers/toolbox][toolbox]].
The containers are cryptographically signed for enhanced security and can be safely used on security-enhanced systems like [[https://secureblue.dev/][secureblue]].

Inspired by [[https://github.com/ublue-os/boxkit][ublue-os/boxkit]], this project provides a streamlined approach to creating and maintaining custom container images with proper signing infrastructure.

** Getting Started

This project provides both pre-built signed images and a framework for creating your own custom signed containers.

*** Prerequisites

- [[https://podman.io/][Podman]] or [[https://www.docker.com/][Docker]]
- [[https://github.com/89luca89/distrobox][Distrobox]] or [[https://github.com/containers/toolbox][Toolbox]]

*** Using Pre-built Images

**** For Regular Container Hosts

#+begin_src bash
# Using distrobox
distrobox create --image ghcr.io/marpogaus/emacs-arch:latest --name emacs-arch

# Using toolbox
toolbox create --image ghcr.io/marpogaus/emacs-arch:latest emacs-arch
#+end_src

**** Declarative Setup with =distrobox assemble=

[[file:distrobox.ini][=distrobox.ini=]] holds one assemble profile per published image. It is generated from
the build matrix, so it always lists exactly the images this repository publishes:

#+begin_src bash
curl -O https://raw.githubusercontent.com/MArpogaus/distrobox-images/main/distrobox.ini

# create a single box
distrobox assemble create --file distrobox.ini --name emacs-arch

# or every box in the file
distrobox assemble create --file distrobox.ini
#+end_src

The file is also attached as an asset to every tagged release. The committed copy
tracks =:latest=; the copy attached to a release pins the release's image tag instead,
so assembling from a release asset reproduces that exact set of images.

Each profile declares its exports with distrobox's own =exported_apps= and
=exported_bins= keys, so creating a box also puts =emacs=, the LaTeX binaries, the AI
CLIs and the Cider and Claude Desktop launchers into =~/.local/bin= and your
application menu. Both keys need absolute paths, and the distros disagree about what
those are: Arch keeps =biber= in =/usr/bin/vendor_perl=, npm's global prefix varies,
Cider's desktop entry is =Cider.desktop= on Fedora, and Claude Desktop's is
=com.anthropic.Claude.desktop=. So every layer follows one rule — link what it exports
into =/usr/local/bin= or =/usr/local/share/applications=, which is all =distrobox.ini=
ever refers to. A tool that is missing breaks the image build, not the user's box.

**** For secureblue and Other Security-Enhanced Systems

If you're running [[https://secureblue.dev/][secureblue]] or similar security-enhanced distributions that enforce container signing policies, you'll need to configure your system to trust the container signatures.

1. Create a registry configuration file:
   #+begin_src bash
     mkdir -p $HOME/.config/containers/registries.d
     cat > $HOME/.config/containers/registries.d/ghcr.io-marpogaus.yaml << EOF
      docker:
        ghcr.io/marpogaus:
          use-sigstore-attachments: true
      EOF
   #+end_src

2. Update your container policy to allow signed images from this repository:
   #+begin_src bash
   # Backup existing policy
   cp /etc/containers/policy.json $HOME/.config/containers/policy.json.bak

   jq '.transports.docker["ghcr.io/marpogaus"] = [{"type": "sigstoreSigned", "keyPath": "/etc/pki/containers/marpogaus-cosign.pub", "signedIdentity": {"type": "matchRepository"}}]' $HOME/.config/containers/policy.json.bak > $HOME/.config/containers/policy.json
   #+end_src

3. Download and install the public key:
   #+begin_src bash
   # Create directory for custom keys
   sudo mkdir -p $HOME/.config/pki/containers

   # Download the public key
   curl -o cosign.pub https://raw.githubusercontent.com/MArpogaus/distrobox-images/main/cosign.pub

   # Install the key
   sudo cp cosign.pub $HOME/.config/pki/containers/marpogaus-cosign.pub
   #+end_src

For rootful Containers container access, you'll need to modify the system policy directly.

*** Creating Your Own Images

To fork this repository and create your own signed container images:

1. *Fork this repository* to your GitHub account

2. *Add your build script(s)* to the appropriate context directory:
   - Create or modify scripts in =context/<distro>/<layer>-build.sh= (e.g., =context/fedora/mylayer-build.sh=)
   - Scripts must use =set -ouex pipefail= and perform their installation/configuration
   - To have distrobox export what the layer installs, link it into =/usr/local/bin=
     (=ln -sf "$(command -v mytool)" /usr/local/bin/mytool=) or
     =/usr/local/share/applications=, then add the layer to the tables in
     =scripts/gen-distrobox-ini.sh=. Never hardcode the tool's real path: =assemble=
     aborts if an exported path is missing, so a wrong guess breaks the user's box,
     whereas a failed link breaks the build where you can see it.

3. *Add the image to the build matrix* in =.github/matrix.yaml=:

   For *multi-layer images*, list the layers in the order they should run:
   #+begin_src yaml
   - image-name: emacs-mytool-fedora
     base-image: quay.io/fedora/fedora-toolbox:latest
     layers: emacs,mytool
     context: fedora
   #+end_src

   For *single-layer images*:
   #+begin_src yaml
   - image-name: mytool-fedora
     base-image: quay.io/fedora/fedora-toolbox:latest
     layers: mytool
     context: fedora
   #+end_src

   The =LAYERS= argument accepts a comma-separated list of build scripts. The
   containerfile template =base.containerfile= handles everything else. Add
   =free-disk-space: true= for images too large to build on a stock runner, and base
   an image on an already-published one (=base-image: ghcr.io/marpogaus/emacs-fedora:latest=)
   if you only want to add a layer on top.

   Run =pre-commit run --all-files= afterwards to regenerate =distrobox.ini=; CI fails
   if it is not in sync with the matrix. This needs [[https://github.com/mikefarah/yq][yq]] on your =PATH=.

4. *Set up container signing* (highly recommended):

   a. Install [[https://docs.sigstore.dev/cosign/installation/][cosign]] locally:

   b. Generate signing keys:
      #+begin_src bash
      cosign generate-key-pair
      # Press Enter when asked for password (leave empty)
      #+end_src

   c. Add the private key to GitHub secrets:
      - Go to your repository Settings → Security → Secrets and variables → Actions
      - Create a new secret named =SIGNING_SECRET=
      - Copy the contents of =cosign.key= into the secret value
      - *Never share or commit the =cosign.key= file*

   d. Replace the public key in the repo with your new one.

5. *Push your changes* and GitHub Actions will automatically build and sign your images
